              Constraint Propagation
Basic principle:

 - Each search node stores variable domains
   (set of values still possible for each variable)

 - Consider each constraint in isolation

 - If certain values are inconsistent, remove them from the domain

 - Only search on values that have not been found inconsistent

                        Some notation
• A domain D maps variables to sets of values, e.g.
 D(x) = {1,3,4,5}
• An assignment a maps variables to values, e.g.
 a(x) = 3
• We will talk about the lower and upper bounds of x in D:
 min(D,x)=min({i | i in D(x)})
 max(D,x)=max({i | i in D(x)})
• We use update operations to modify a domain:
 D(x) := {1,3,5}         (set domain of x to {1,3,5})
 D(x) := D(x) \ {3}      (remove 3 from domain)
 D(x) :≤ 4               (remove all values > 4)
                                                             10
                            More notation
A propagator is a function that takes a domain as input and returns an updated domain

 - we will use := to simplify notation

 - returning an empty domain signals failure (domain wipeout)

Propagators must be

 - correct (only remove values that are inconsistent)

 - checking (signal failure when only one value per variable is left)

 - monotonic (do at least the same amount of pruning on smaller domains)

Propagators can be

 - idempotent ( p(p(D)) = p(D) )

Simple rule-based propagation:

D(x) :< max(D,y)
D(y) :> min(D,x)
• Q: is this propagator idempotent?
 (i.e., after applying both rules, can we prove that they never " re" immediately
 again?)
• A: yes, because we only read the max (min) of y (x) but update the min (max)

Again simple rules:

if D(x) = {d} then D(y) := D(y) \ {d}
if D(y) = {d} then D(x) := D(x) \ {d}
• Q: is this propagator idempotent?

• A: yes

          Propagation rules for x≤y+z
• Isolate each variable in turn:

 - D(x) :≤ max(D,y)+max(D,z)

   D(y) :≥ min(D,x)-max(D,z)

   D(z) :≥ min(D,x)-max(D,y)
• Observation 1: these rules are complete, they remove all possible
 inconsistent values
• Observation 2: all complete propagators are idempotent

          Propagation rules for x=y+z
• Isolate each variable in turn:

 - D(x) :≤ max(D,y)+max(D,z)
   D(x) :≥ min(D,y)+min(D,z)
   D(y) :≥ min(D,x)-max(D,z)
   D(y) :≤ max(D,x)-min(D,z)
   D(z) :≥ min(D,x)-max(D,y)
   D(z) :≤ max(D,x)-min(D,y)
• Q: are these rules complete?

• A: no, counterexample: x,y∈{1,3}, z∈1..8

• This is an example of bounds propagation

                  Bounds vs Domain
• Strongest possible propagation:
 a propagator is complete for a constraint c if after propagation, no further
 value could be removed from any variable domain because of constraint c
• Complete propagators are also called domain consistent

• Often algorithms for complete propagators are computationally expensive or
 even NP hard!

 - example: y = sum (i in 1..n) (c[i] * x[i])

• Bounds propagation ignores "inner" domain values and only looks at min/
 max


                                                                                18
                 Bounds Propagation
• Let's design propagation rules for x = a×y + b×z

 - D(x) :≤ a×max(D,y)+b×max(D,z)
   D(x) :≥ a×min(D,y)+b×min(D,z)
   D(y) :≥ (min(D,x)-b×max(D,z)) / a                   y = (x-b×z)/a
   D(y) :≤ (max(D,x)-b×min(D,z)) / a
   D(z) :≥ (min(D,x)-a×max(D,y)) / b                   z = (x-a×y)/b
   D(z) :≤ (max(D,x)-a×min(D,y)) / b
• Q: are these rules bounds complete? (i.e. do they prune the bounds as
  much as possible)
• A: no, counterexample x=3y+5z, x∈2..7, y∈0..2, z∈0..1

 - reason: the rules above compute with real numbers

                              Matching
• A matching is a subset of edges in a graph such that
 no two edges share a common vertex
• A matching is maximal if the cardinality is maximal

• Q: When is a matching maximal in a bipartite graph?

• A: In a bipartite graph, a matching is maximal if it maximally covers one of the
 two sets of nodes

 - in our case: the set of variable nodes needs to be completely covered,
   since we need at least one value for each variable!

                  Matchings are Solutions
• An assignment a is a solution to the alldifferent constraint


 if and only if

 xi → a(xi)

 is a maximal matching

 - No value has two incoming edges
   (no two variables have the same value)

 - All variable nodes are covered
   (we have a value for each variable)
• If an alldifferent constraint has a solution at all, then the solutions correspond to the
 set of maximal matchings

                                  Fixed points
• Putting it all together:

 - one or more propagators per (high-level) constraint

 - at each search node, run all of them until none can contribute any more: this
   is a mutual xed point of the propagators

 - we can prove: because propagators are monotonic, the order of
   propagation does not matter, we always get the same xed point!

 - But: order may matter for ef ciency

                         E cient Fixed Points
      Two typical techniques for making xed point computation ef cient:

       - keep a queue of propagators that may still be able to contribute
         • initially all propagators

         • remove after propagation if no variable was changed

         • advanced: priority queue (cheap propagators   rst)

       - only run propagators whose variables have changed
         • don't run x<y if only z has changed

         • don't run x<y if only the lower bound of y has changed!

         • this is called event-based propagation

                            Scheduling
• Constraints: disjunctive, cumulative

• Algorithmic ideas:


 disjunctive: For every set of tasks on the machine, compare the total
 processing time with the span from its earliest start to its latest end; if it
 doesn't t, deduce that some task must come before or after the whole set
 (edge nding, all sets in O(n log n) via a Θ-tree).

 cumulative: Build the compulsory-part pro le (the time each task must be
 running whatever its start) and push tasks out of over-capacity regions;
 strengthen with energetic reasoning — compare the energy available in a
 window, capacity × length, with the energy the tasks must spend inside it.

                                  Counting
• Global cardinality constraint

• Algorithmic idea: basically an extension of all-different. Each value gets a
 capacity interval, so domain consistency is a feasible ow in the value graph,
 and any arc in no feasible ow is pruned (residual-graph SCCs, exactly as in
 Régin's alldifferent).
• Note that alldifferent(x) is the same global_cardinality(x, [0,…,0], [1,…,1]):
 each value may appear between 0 and 1 times!

                        Table constraints
• State that an array of variables x must take the values of some tuple t from a
 list of given tuples
• Can express arbitrary constraints (although the list of tuples can get
 exponentially long)
• Algorithmic idea: Keep, for every value, whether any allowed tuple still
 supports it; the modern version stores the tuple set as a bitset and updates it
 by word-parallel AND (compact-table), which is why table constraints are fast
 in practice.

                 Grammar constraints
• E.g. regular(x, r) states that the x variables must be a word in the regular
 language r
• Algorithmic idea: Unfold the automaton into a layered graph, one layer per
 variable, and keep only the arcs that lie on some accepting path — a
 reachability sweep forwards and backwards.

                   Element constraint
• The simple constraint y = a[x], where x, y and a can all be variables

• Algorithmic idea: drop any x whose entry is no longer in D(y), and any y value
 no surviving index produces. Plus extensions when the a are variables.

                     Graph constraints
• E.g. circuit(x) states that the x variables must form a Hamiltonian circuit

• Algorithmic idea: forbid the arc that would close a subtour before all nodes are
 in, and use structural relaxations (connectivity, mandatory bridges/articulation
 points, 1-tree bounds) because checking Hamiltonicity itself is NP-hard.
