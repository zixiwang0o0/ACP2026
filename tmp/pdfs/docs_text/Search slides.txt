          CP=Propagation + Search
• Reminder:

 - generate and test:
   use backtracking search to generate assignments to variables, then check
   constraints

 - constraint programming:
   at every search node, propagate constraints to remove inconsistent values
• Constraint propagation prunes the search tree

• Now: branching heuristics determine the choices that are made at each
 node

                                Branching
• At each node, the solver needs to make a choice

• Usual case (in CP):

 - pick a variable      x that still has at least two values

 - pick a value         v from the domain of x

 - branch with          x=v   and x≠v
• Heuristic needed: which x and which v?

• Most CP solvers use this pattern

                   Branching and Exploration
• The choices de ne the shape of the tree

• An exploration strategy de nes the order of exploration:

      - DFS                  depth- rst left-to-right

      - BFS (breadth- rst), LDS (limited discrepancy), ID (iterative deepening), A*
        (best- rst search), parallel, …
• The two interact:

      - if heuristic tries to put solutions towards the left of the tree, we should use
        left-to-right exploration!

                 Branching Heuristics
• Programmable heuristics:

 - use domain knowledge (application speci c search, e.g. scheduling, packing,
   geometric problems, routing)
 - require insight into problem structure
 - can be a big advantage of CP solvers
• Universal heuristics:

 - no user interaction needed ("black box" solver)
 - dominant in SAT, MILP
 - current research topic in CP
• In between:

 - commonly used (generic) CP heuristics

              Adaptations of rst-fail
• Pick the most constrained variable

 - degree = how many constraints are attached (solver needs this anyway!)

 - order by domain size / degree
• Pick the variable that was responsible for most of the recent failures

 - keep track of which variables cause failure

 - weighted degree = degree weighted by failure counts

 - similar to standard heuristic in SAT (called VSIDS)

                 Heuristics in MiniZinc
• Search can be controlled using annotations on the solve item

• For integer variables:
 int_search(vars, var_sel, val_sel, complete)

 - vars is an array of variables

 - var_sel is the variable selection strategy
   (input_order, first_fail, anti_first_fail, smallest, largest,
   occurrence, most_constrained, max_regret,
   dom_w_deg)

 - val_sel is the value selection strategy
   (indomain_min, indomain_max, indomain, indomain_split)

                      Value selection
• Choice: x=n, x≠n

 - indomain_{min,max}: n = {smallest,largest} value in domain
 - indomain_median: n = median value in domain
 - indomain_random: n = random value from domain
• Choice: x=d1, x=d2, … x=dn

 - indomain: try domain values from lowest to highest
• Choice: x≤d, x>d

 - indomain_split: d=(min(D,x) + max(D,x)) / 2
 - indomain_reverse_split: swap ≤ and >

                     Complex Search
• MiniZinc supports only one complex search combinator:
 seq_search([s1,…,sn])

 - complete search si before starting search si+1

 - e.g. consider two arrays of variables:
   vehicle[c] maps customer c to a vehicle
   arrival[c] maps customer to arrival time of vehicle

 - possible strategy: rst decide vehicle mapping, then arrival times:
   seq_search([int_search(vehicle,…,…,…),
                    int_search(arrival,…,…,…)]);

     • So far: how to   nd a satisfying solution
     • To solve optimisation problems, we use
      branch and bound search:

      - search for a solution

      - compute its objective value

      - post a constraint for the remaining search to only allow solutions with better
        objective value

      - repeat until no more solutions are found
     • The   nal solution is guaranteed to be optimal

                       Restart strategies
• Policy for when to restart

 - Constant restart – after using L resources

 - Geometric restart
   • restart after using L resources, with new limit α L

 - Luby restart
   • 1,1,2,1,1,2,4,1,1,2,1,1,2,4,8, …

   • "universally optimal" for randomised algorithms:

     •   no worse than a log factor slower than optimal policy
     •   not bettered by more than a constant factor by other universal policies

                               Restarts
• Restarts are ubiquitous in default search strategies

• Combined with dynamic variable selection strategies they have another
 advantage

 - A bad choice at the top requires exponential search to undo

 - Restarts avoid this, by throwing away the choice.

              Large Neighbourhood Search
     • Basic principle:


      - nd initial solution (using CP, or any other method)

      - destroy parts of it (reset variables to full domains)

      - repair by re-solving

     • Control overall search using a meta heuristic (e.g. hill climbing or
      simulated annealing)

     • Has proven very successful for hard problems (e.g. vehicle routing,
      scheduling, rostering)

Limitations
                             Limitations
CP works well for many types of problems, but there are limits:
•   Very large number of variables and constraints
•   Continuous variables
•   Problems with strong LP relaxations
•   Problems where nding solutions is easy (and there are very many) but nding
    good solutions is hard
